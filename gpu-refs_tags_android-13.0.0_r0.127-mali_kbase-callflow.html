2. Job Scheduler (JS Context)

This section covers 41 JS nodes and 77 internal edges; the first tree shows the end-to-end ioctl path.

主要内容与流程

本章从 UMD ioctl 进入驱动，经 Job Dispatcher（JD）落到 Job Scheduler（JS）。JM 路径下用户态提交命令为 KBASE_IOCTL_JOB_SUBMIT（CSF 路径则是 CS_QUEUE_KICK，不走本 JS 树）。

JS 负责每个 kbase_context 上的软件队列：作业树、优先级 ringbuffer peek/pull、依赖校验与提交。主要代码：mali_kbase_core_linux.c → mali_kbase_jd.c → mali_kbase_js.c / mali_kbase_jm.c。

kbase_js_pull() 唯一调用点是 kbase_jm_next_job()（mali_kbase_jm.c）；上游经 kbase_jm_kick / try_kick，常见触发为 kbase_js_sched、活跃 ctx 上 add_job 快路径，以及 JOB IRQ 完成后的 refill。

触发 → kbase_jm_kick / try_kick → kbase_jm_next_job → kbase_js_pull → kbase_backend_run_atom → HW submit
