GPU 分时方案

Host（Linux）和 Guest（Android）各带一套 GPU 驱动，由仲裁器按时间片轮流使用同一块物理 GPU。六张图依次回答：谁和谁通信，仲裁器怎么切，一个时间片怎么走完，guest 驱动怎么响应，电源与调频怎么配合。

Host 与 Guest 谁在哪一侧

Guest 的仲裁消息不直接发给仲裁器，先出 guest 内核，经 HVC / vclink 到 host 一侧的 guest_xenback，再进 mali_arbiter。

图 2

Host 仲裁器：四态状态机

只有 1 个请求时独占 GPU，不分时；第 2 个 VM 入队后进入分时轮转。

算法

req_list 上的 FIFO round-robin：入队尾、取队首、让出后回队尾。无优先级、权重、配额。

两个定时器

req_tmr 是时间片，只在 ARB_RUNNING（多 VM 竞争）时启动；stop_tmr 是让出看门狗，2000 ms。

时间片时长

host（id=0）linux_request_timeout 7 ms；guest android_request_timeout 8 ms。都是硬编码的 static 值。

idle 抢占

VM 发 VM_ARB_GPU_IDLE，仲裁器停掉 req_tmr 并立即 stop_gpu，不等时间片到。

图 3

一个时间片的完整生命周期

从授予 GPU 到切走，共六步；VM 正常让出走①→⑤并回到①，不让出则走⑥。

  1. ①

    授予 + 起片

    run_next_vm_locked→grant_gpu_to_next_locked取队首，经 HVC 发 GRANTED
    →start_req_timer_locked(7/8ms)启动 req_tmr
    VM 在这个时间片内正常渲染。
  2. ②

    片到期（硬中断）

    req_timer_isr:1264
    中断里只 queue_work，不拿锁。
  3. ③

    处理到期

    req_timeout_worker:1994
    state == ARB_RUNNING→stop_gpu_locked:2028
  4. ④

    通知让出

    stop_gpu_locked:1819
    set_state(ARB_GPU_STOPPING):1839
    start_stop_timer_locked(yield_timeout=2000ms)让出看门狗:1847
    active_vm->info.ops.gpu_stop(vm)发 ARB_VM_GPU_STOP:1848
    VM 停手并 flush，回到 STOPPED。
  5. ⑤

    VM 已停，切下一个

    gpu_stopped(arb_vm, req_again):1615
    wake_up(vm_stopped_wait)grant_state = 0:1657–1665
    if (req_again) list_move_tail(&entry, req_list)让出者回队尾:1674
    else list_del_init(&entry):1669
    remove_active_vm(partition):1677
    run_next_vm_locked(partition)回到 ①，切下一个:1680
  6. ⑥

    强制夺回（VM 超时不让）

    stop_timer_isr:1281→stop_timeout_worker:2038→handle_gpu_lost_locked:1858
    active_vm->info.ops.gpu_lost(vm)发 ARB_VM_GPU_LOST，强切下一个

Guest kbase：VM 状态机

仲裁器发来 GRANTED / STOP，guest 驱动据此在“持有 GPU”和“不持有 GPU”之间切换。

启动时被收回

STARTING 状态收到 GPU_STOP_EVT，直接转 STOPPING_ACTIVE，图里没有画这条线。

OS 休眠路径

STOPPING_*OS_SUSPEND →SUSPEND_PENDING→SUSPENDED
STOPPED_GPU_REQUESTEDOS_SUSPEND →SUSPEND_WAIT_FOR_GRANT→SUSPENDED
SUSPENDEDOS_RESUME →STOPPED_GPU_REQUESTED（重新申请）
